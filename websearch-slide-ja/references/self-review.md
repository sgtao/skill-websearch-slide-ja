# Self Review — 生成後の自己検証（v0.8.6）

HTML を生成したあと、ユーザーに提示する**前**に行う確認の手順。
SKILL.md Step 5-B から参照する。変換の成功や lint 0 件は、見た目の確認の代わりにならない。

---

## 1. 検証の段階

| 段階 | 内容 | 対象 | 実行条件 |
|---|---|---|---|
| L1 | lint の確認（`cli-conversion.md`「lint の扱い」） | CLI トラック | 毎回 |
| L2 | `validate-output.sh`（`output-validation.md`） | レガシートラック | 毎回（シェルを実行できる環境） |
| L3 | スライドを撮影し、画像を自分で見て直す | 両トラック | Playwright が使えるときだけ |

- L1・L2 を通してから L3 に進む（構造が壊れた HTML を撮影しても意味がない）
- 行えなかった段階は、完了報告の 6（未実施の検証）に理由つきで書く（§6）
- どの段階も、**足りない道具を自動でインストールしない**

---

## 2. L3 の手順

### 2-1. 撮影する

スキルのフォルダを基準に実行する（シェルの手段と保存先は `environment.md` §1）。

```bash
node assets/scripts/capture.mjs <成果物の保存先>/{テーマ}-slides.html
```

| 終了コード | 意味 | 次の動作 |
|---|---|---|
| 0 | 撮影できた | 2-2 へ |
| 3 | Playwright が使えない（未導入、またはブラウザ本体が未導入） | **L3 を飛ばす**。エラーとして扱わない。インストールを試みない |
| 1・2 | 撮影中のエラー、引数・ファイルの誤り | 1 回だけ原因を確かめて再実行。直らなければ L3 を飛ばす |

- 画像は成果物の隣の `.work/` に保存される（`sNN.png`、960×540）。置き場を変えるときは
  `--out <dir>`（Claude.ai では作業用ディレクトリ。`environment.md` §1）
- `.work/` は確認のあとも**消さない**（ユーザーが画像を見返せる）。再撮影のたびに中身は入れ替わる
- 既定のテーマで 1 回だけ撮る。もう一方のテーマを見るときは `--theme dark`（または `light`）
- **16 枚を超えるとき**だけ、撮影の前に選択式で確認する
  （「全スライドの見た目を確認する／見た目の確認はしない」）。16 枚以下は確認せずに撮る

### 2-2. 測定結果を読む

標準出力（と `.work/capture-report.json`）に、機械的に測った結果が出る。

| 項目 | 意味 | 使い方 |
|---|---|---|
| `overflowSlides` | 枠の外に要素が出ているスライド番号（1 始まり。`slide-fit` を除く） | 必ず画像で確かめて直す |
| `slides[].overflowPx` | 枠から出ている最大の長さ（px） | 大きいほど削る量が多い |
| `slides[].clippedElements` | 途中で切れている要素の数 | 1 以上なら画像で文字切れを確かめる |
| `slides[].textLength` / `media` | 文字数／図・表・画像・コードの数 | 両方が小さいスライドは「空に近い」候補 |
| `slides[].fit` / `listFile` | `slide-fit` のスライドと、その一覧表示の画像 | §3 の注意を参照 |
| `externalFailed` | 読み込めなかった外部ファイルの数 | 1 以上なら §5 に従う |

測定は見落としを減らすための補助であり、合否の判定ではない。数値が 0 でも画像は見る。

### 2-3. 画像を見る

**全スライドを見る**（抜き取りにしない）。画像を読めるツールで `sNN.png` を 1 枚ずつ開く。
`slide-fit` のスライドは `sNN-list.png` も見る。

### 2-4. 直して撮り直す

- CLI トラック: **MD を直して再変換**する（HTML を直接書き換えない）
- レガシートラック: HTML を直し、MD も同じ内容に合わせる。直したら L2 をもう一度通す
- 「直す → 再変換 → 再撮影」を 1 周とし、**上限は 2 周**。2 周で直らない指摘は、
  それ以上直さずに完了報告の 6 に書く
- 直したスライドだけでなく、再撮影後は全スライドを見直す（直した影響で別のスライドが崩れることがある）

## 3. 見る観点と直し方

| 観点 | 見つけ方 | 直し方（MD に対して） |
|---|---|---|
| はみ出し・文字切れ | `overflowSlides`、枠の端で切れた見出し・最終行 | スライドを 2 枚に分ける／文を短くする／項目を減らす。10 行を超える表・20 項目を超える一覧だけ `, fit` を付ける |
| 文字の重なり | 文字どうし、文字と図が重なっている | 行数・項目数を減らす。図解はラベルを短くする |
| 空に近いスライド | 文字数も図も少なく、余白が大半 | 前後のスライドに統合する。**内容を作り足して埋めない** |
| グラフ・図解の崩れ | 軸ラベルの欠け、凡例の重なり、矢印のずれ | データ点・系列を減らす。直らなければ表に切り替える |
| `tone: dark` の使いすぎ | 暗いスライドが 3 枚以上 | 強調したい 1〜2 枚に絞る |
| 書いたはずの内容が出ていない | 見出しだけのスライド、行が抜けた一覧（lint は 0 件でも起こる） | 記法を実効仕様に合わせる（例: `sources` はリンクの形 `- [名前](URL)` で書く。URL が無い出典は `- [ユーザー提供](#)`。`points` の見出しは `##`） |
| 読みにくい文字 | 帯や色つきの面で文字が沈んでいる | 記法を変える（例: `point:` の帯にインラインコードを書かない） |

直すときの制約

- **`（要確認: …）` を消したり、値で埋めたりしない**。要確認があるスライドは「空に近い」の
  指摘対象から外す（埋める圧力を作らないため。SKILL.md Step 4-A）
- はみ出しを直すために、出典・数値・固有名詞を削って意味を変えない。削るなら説明文から削る
- `slide-fit` のスライドは、1 枚表示では下が切れるのが仕様（一覧表示で全体が見える）。
  `sNN.png` が切れていても指摘にせず、`sNN-list.png` で崩れていないかだけを見る
- 見た目の好み（色・余白の微調整）では直さない。上の表にある崩れだけを対象にする

## 4. ユーザーが用意した MD のとき（エントリポイント B / D）

撮影と確認は同じように行うが、**本文は書き換えない**（SKILL.md Step 4-A の適用範囲と同じ）。
見つけた指摘はスライド番号つきで伝え、直すかどうかを選択式で確認する。

---

## 5. 外部ファイルが読めなかったとき

`externalFailed` が 1 以上のとき（オフラインや通信制限でフォント・画像が読めない環境）は、
画像の見た目が実際の表示とずれている。

- 文字幅・行の折り返しに由来する指摘（はみ出し・文字切れ）では**直さない**
- 画像の欠け（代替表示になっている）も、撮影環境の制約として扱う
- 完了報告の 6 に「外部ファイルを読めない環境で撮影したため、見た目の修正は見送り」と書く

---

## 6. 完了報告の 6（未実施の検証）への書き方

行っていない確認を先に書き、行った見た目の確認は括弧で添える。1 行に収める。

| 状況 | 6 の書き方の例 |
|---|---|
| L3 を行い、直す箇所が無かった | `出典 URL が開けるかの確認（見た目は全 12 枚を撮影して確認・修正なし。画像: ./.work/）` |
| L3 を行い、直した | `出典 URL が開けるかの確認（見た目は全 12 枚を撮影して確認・2 枚を修正。画像: ./.work/）` |
| 2 周で直らない指摘が残った | `スライド 7 の表のはみ出しが未解消（見た目は全 12 枚を撮影して確認・2 周で打ち切り。画像: ./.work/）` |
| Playwright が無い | `見た目の目視確認（Playwright が無いため撮影していません）` |
| シェルを実行できない | `見た目の目視確認、機械的な検証（この環境ではシェルを実行できません）` |
| 16 枚超でユーザーが見送った | `見た目の目視確認（枚数が多いため、ご指定により見送り）` |
| 外部ファイルが読めなかった | `見た目の修正（外部ファイルを読めない環境で撮影したため見送り。画像: ./.work/）` |

- 撮影したのが片方のテーマだけなら、括弧の中に「ライトのみ」「ダークのみ」と添える
- 撮影していないのに「見た目を確認しました」と書かない。撮影しても見ていない画像があれば、
  見た枚数を正しく書く
- レガシートラックで L2 を通したときは、6 から `validate-output.sh` を外す。FAIL が残ったら
  その項目名を 6 に書く

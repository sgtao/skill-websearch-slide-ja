# build — CLI診断・MD→HTML変換・出力と自己検証（各モードで共通）

> create / convert-md / convert-raw / edit から参照する共通手順。
> 先に読むもの: `references/environment.md`、`references/cli-conversion.md`。
> レガシートラックになったときだけ `workflows/legacy-build.md` を読む。

## Step 2.5: CLI環境診断＋実効仕様の取得（プリフライト）

**構成を決める前に**、この会話内でまだ診断していなければ必ず実行する
（詳細は `references/cli-conversion.md` §2〜§3）。エントリポイント B / C では変換・逆抽出の直前に実行する。

このスキルは **CLIトラック**（`mdss-convert` に変換を委譲）と **レガシートラック**
（従来どおりLLMが直接HTMLを生成）の2経路を持つ。どちらになるかはこのステップで決まり、
以降の Step 3-0・3・4-A・4-B・5 の手順がトラックによって変わる。

1. `mdss-convert`（グローバル）または `npx -y mdss-convert@latest` が使えるか確認する
2. 使える場合、`--help` の出力から対応オプション（`--print-spec` / `--strict` /
   `--json-only` / `--extract-md` / `--guide-prompt` 等）と **`--palette` に並ぶパレットID** を確認する
3. **実効仕様を取得する**（CLIトラックのみ。会話内で各1回）
   - `--print-spec` 対応 → 実行して読む。**これが記法の正**（type 一覧・共通記法・`layout:`・制約・枚数の目安）
   - `--guide-prompt` 対応 → 実行して読む。**「type の選び分け指針」と「構成フレーム」だけを参考にする**。
     原稿作成をこのプロンプトに丸ごと任せない（目的確認・検索・出典管理は本スキルの役割）。
     記法の説明が `--print-spec` と食い違う箇所は `--print-spec` を正とする
   - `--print-spec` 非対応 → `references/markdown-format.md` を実効仕様とする
4. 判定結果（トラック・対応オプション・パレットID・実効仕様）は会話内で保持し、
   以降 Step 4-B を複数回実行しても再診断・再取得しない
5. 利用不可の場合は「今回はCLIが利用できないため、従来方式で作成します」と一言添え、
   以降はレガシートラック（[レガシー] 表記の手順）で進める。実効仕様は
   `references/markdown-format.md` と `references/slide-layouts.md`

## Step 4: スライド生成（MD中間層）

> 生成は「4-A: スライドMD生成 → 4-B: MD→HTML変換」の2段構成（CLI環境診断は Step 2.5 で済んでいる）。
> スライドMD が Single Source of Truth（正）であり、HTML は MD から毎回フル再生成する。
> エントリポイント B（MD添付）では Step 2.5 → 4-B の順で実行する（4-A はスキップ）。

トラック（CLI / レガシー）は Step 2.5 の診断結果で決まっており、経路によって Step 4-A・4-B の
具体的な手順が変わる。詳細な判定ロジックとコマンド組み立ては `references/cli-conversion.md` を参照。

Step 4-A（スライドMD生成）は `workflows/write-md.md`。

### Step 4-B: MD→HTML変換

```
CLIトラック:
  references/cli-conversion.md §4 のコマンド組み立てに従い、mdss-convert で変換する。
  変換結果（--json の warnings / lint）は必ず読み、次の「lintの扱い」で判定する。
  --strict が通った（exit 0）だけでは合格にしない

レガシートラック [レガシー]:
  `workflows/legacy-build.md` の「生成手順」でLLMが直接HTMLを生成する
```

**lintの扱い（CLIトラック）**: `--strict` が止めるのは一部の error だけで、出典なしのグラフや
未知の type は warn のまま exit 0 になる（HTMLも出力される）。warn / error が1件でもあれば
内容を読み、下表に当てはめる（メッセージ文言の一致ではなく、内容で判断する）。

| lint / warnings の内容 | 扱い |
|---|---|
| `level: "error"`（`--strict` では exit 3・HTML未出力） | HTMLを提示しない。MDを直して再変換 |
| 出典が無い（chart / figure の `source`）・未知の type・最終スライドが `sources` でない（3枚ミニモードを除く） | **error と同じ扱い**。HTMLを提示せず、MDを直して再変換 |
| ブロックの形式不正（グラフ・図が描画されない）・切り捨て（系列数・ノード数・項目数の超過）・不正値のフォールバック | 内容が欠けるため、MDを直して再変換 |
| 上記以外の warn / info（例: 外部画像のCORS注意） | 再変換は不要。完了時に要約して伝える |

再変換は対象の warn / error が 0 件になるまで行う。
- **ユーザーが用意した MD・データ（エントリポイント B / D）で出典が無い場合**: 勝手に削らず、
  まず出典をユーザーに確認する。ユーザー自身のデータなら `source` に「ユーザー提供データ」と書く
- **出典が確認できないグラフ**（確認しても不明、または確認できない状況）: 数値を作らず、
  そのスライドを `points` 等のテキストに置き換え、置き換えたことを完了時に伝える
事前確認だけしたいときは `--json-only`（HTMLを出さずに lint だけ見る）を使ってよい。

frontmatter `palette` があれば `<html data-palette="...">` を焼き込み、
ドロップダウンの該当ボタンへ `is-active` を移す（`markdown-format.md` §6 / CLIトラックでは
mdss-convert側が同等の処理を行う）。

> 文言のトーン・強調・ネクストアクションは、Step 0 で確認した作成目的
> （`references/audience-purpose.md`）に従う。両トラック共通。

生成後の修正（スタイル変更の対話）は `workflows/edit.md`。

### デザイン原則

- フォント: Noto Sans JP（本文）+ JetBrains Mono（コード）
- アクセントカラー 1 色のみ（`--accent`）。パレットは生成後に HTML 右上の 🎨 メニューで切替可能（生成時のデフォルト: ocean）
  - CLIトラック: 使えるIDは **`--help` の `--palette` に並ぶもの**（v0.6.1 では ocean / ruby / forest / sunset / plum / gold / graphite の7色）。`--print-spec` の表と食い違う場合は `--help` を正とする
  - レガシートラック: 5色（ocean / forest / sunset / plum / graphite）。それ以外のIDを指定されたら ocean にして、その旨を伝える
- 文字中心・広い余白・箇条書き主体
- スライドサイズ: 960×540px 固定（16:9）、`transform: scale()` でフィット
- 両トラック共通の見た目方針。詳細な実装（CSS変数の値等）は `references/design-tokens.md`
  [レガシー]（CLIトラックではmdss-convert側が担うため参照不要）

### エクスポート機能

生成 HTML は以下 3 種に対応（両トラック共通）。レガシートラックの実装詳細は
`references/export-recipes.md` [レガシー]。CLIトラックはmdss-convertが標準で備える
（キー操作は版で変わりうるため、CLIトラックでは生成HTML上の `?` キーの一覧を正とする）。

| 方式 | 起動 | 依存 | 自己完結性 |
|------|------|------|-----------|
| PDF（印刷経由） | `P` キー / 📥メニュー | 標準 `window.print()` | ◎ オフライン可 |
| 単一 PNG | `Shift+S` / 📥 | html2canvas（CDN 動的ロード） | △ ネット必須 |
| 全スライド ZIP | `Shift+P` / 📥 | html2canvas + JSZip（CDN 動的ロード） | △ ネット必須 |

閲覧は完全自己完結、エクスポート時のみ CDN を動的ロード。`P` キー経由でも `Ctrl+P` 直接でも 1 ページ = 1 スライドになるよう `print.css` が hero モードを上書きする。

`workflows/legacy-build.md` を読む。**CLIトラックの場合は読まない**
（Step 4-BのCLIコマンド1回で完結する）。

## Step 5: 出力・検証

### 5-A. ファイル出力

- ファイル名: `{テーマ}-slides.html` と `{テーマ}-slides.md`
- 保存先: 環境ごとの成果物の保存先（`references/environment.md` §1・§4）
- **`.md` と `.html` の両方**を保存して提示する（`.html` を先頭に。提示の手段は同 §1）
- **提示の前に 5-B の自己検証を行う**（保存 → 自己検証 → 提示の順）
- 提示と同時に、下の「完了報告」を毎回出す
- 操作の案内（完了報告の 7 に添える）はトラック別にする
  - **CLIトラック**: 「`?` キーで操作一覧を表示できます」を基本に、主なキーだけ添える
    （`T` サムネイル帯 / `G` 一覧グリッド / `J` ページ移動）。
    `note:` を書いたデッキに限り「`N` キーで補足ノートを読めます」と伝える
    （ノートが無いデッキでは `N` は案内しない）
  - **レガシートラック**: 従来どおり（`←→` 移動 / `Space` 次へ / `F` フルスクリーン /
    `V` 一覧切替 / `P` PDF / `Shift+S` PNG / `Shift+P` ZIP）

**完了報告（毎回・必須 7 項目）**

HTML を生成・再生成して提示するたびに、次の 7 項目を**各 1 行**で報告する（スタイル変更後の
再変換を含む）。項目は省略しない。該当が無い項目は「なし」、その経路で行わない項目は
「対象外」と書く。前置きやまとめの文は足さない。

| # | 項目 | 書く内容 |
|---|---|---|
| 1 | 生成物 | `.html` と `.md` の保存先パス、枚数 |
| 2 | トラック | CLI（版つき。例: `mdss-convert v0.6.1`）／レガシー |
| 3 | lint | error / warn / info の件数と、残った warn / info の要約。レガシートラックは「対象外（lint なし）」 |
| 4 | 要確認 | 件数と一覧（スライド番号: 確認する内容）。無ければ「なし」 |
| 5 | 情報ソース | 会話のみ／ハイブリッド／Web 検索、出典の件数。ユーザーの MD をそのまま変換したときは「ユーザー提供の MD」 |
| 6 | 未実施の検証 | 行っていない確認を具体的に書く（例: 見た目の目視確認／出典 URL が開けるかの確認）。5-B で見た目を確認したときは、その範囲を括弧で添える（書き方は `references/self-review.md` §6） |
| 7 | 次にできること | `.md` を編集して「変換して」と送れば再生成できること。続けて操作の案内 |

- スライド番号は 1 始まり（表紙が 1）。lint の `slide` は 0 始まりなので 1 を足す
- 要確認が 3 件を超えるときだけ、4 の行に件数を書き、その下に 1 件 1 行で並べる。
  会話に出ていた値がある場合は「（会話では ○○）」と添える
- 6 は、実際に行ったことだけを検証済みとして扱う。変換が成功したこと・lint が 0 件であることは
  見た目の確認にはならない。行っていない確認を「問題ありません」と書かない
- 出典が確認できずテキストに置き換えたグラフ（Step 4-B）は、4 に含める

```
例（CLIトラック・会話のみ）:
1. 生成物: ./skill-improvement-slides.html / ./skill-improvement-slides.md（12 枚）
2. トラック: CLI（mdss-convert v0.6.1）
3. lint: error 0 / warn 0 / info 0
4. 要確認: 2 件（スライド 4: 導入社数の最新値（会話では 300 社）／スライド 9: 処理時間の短縮率）
5. 情報ソース: 会話のみ（出典 0 件）
6. 未実施の検証: 出典 URL が開けるかの確認（見た目は全 12 枚を撮影して確認・1 枚を修正。画像: ./.work/）
7. 次にできること: .md を編集して「変換して」と送ると再生成できます。? キーで操作一覧を表示できます
```

### 5-B. 生成後の自己検証（毎回・提示の前）

HTML を生成・再生成したら、提示の前に次の段階を順に行う。詳細は `references/self-review.md`。
**足りない道具を自動でインストールしない**。行えなかった段階は、完了報告の 6 に理由つきで書く。

| 段階 | 内容 | 対象 | 実行条件 |
|---|---|---|---|
| L1 | lint の確認（Step 4-B「lintの扱い」の表） | CLIトラック | 毎回 |
| L2 | `bash assets/scripts/validate-output.sh {出力ファイル}` | レガシートラック | 毎回（シェルを実行できる環境） |
| L3 | `node assets/scripts/capture.mjs {出力ファイル}` で撮影し、画像を自分で見て直す | 両トラック | Playwright が使えるときだけ |

**L2（レガシートラック）**: FAIL があれば、ユーザーに確認せずに該当箇所を直して再実行する
（上限 2 回）。FAIL が残ったら、その項目名を完了報告の 6 に書いて提示する。WARN は 6 に書く。
検証項目は `references/output-validation.md`。

**L3（両トラック）**

1. `capture.mjs` を実行する。**終了コード 3（Playwright が使えない）なら L3 を飛ばす**。
   エラーとして扱わず、完了報告の 6 に「見た目の目視確認（Playwright が無いため撮影していません）」と書く
2. 画像は成果物の隣の `.work/` に保存される（`sNN.png`）。確認のあとも消さない
3. 測定結果（`overflowSlides` など）を読み、**全スライドの画像を見る**（抜き取りにしない）
4. はみ出し・文字切れ・重なり・空に近いスライド・グラフや図解の崩れ・`tone: dark` の使いすぎを直す。
   CLIトラックは MD を直して再変換する。「直す → 再変換 → 再撮影」は**上限 2 周**
5. `（要確認: …）` は消さず、値で埋めない。ユーザーが用意した MD（エントリポイント B / D）は
   本文を書き換えず、指摘を伝えて直すかを確認する
6. 16 枚を超えるときだけ、撮影の前に選択式で確認する
   （「全スライドの見た目を確認する／見た目の確認はしない」）

**ユーザーが「品質を確認して」「検証して」「チェックして」と求めたとき**: 上の段階をもう一度
実行し、結果を報告する。

- CLIトラック: lint の結果（error / warn / info の件数と内容）と、L3 の結果を伝える。
  `validate-output.sh` は対象外（レガシートラック向けの HTML 実装チェックのため）
- レガシートラック: `validate-output.sh` の結果を伝える。ALL PASS なら
  「検証完了: 全チェック項目を PASS しました。」と報告する。自動修正で直らなかった FAIL が
  あるときは、項目を整理して提示し、選択式で確認する

```
質問: チェック結果に問題がありました。修正しますか？
選択肢:
  - 「はい、修正する」
  - 「いいえ、このままでOK」
```

- **「はい、修正する」** → FAIL 箇所を修正して HTML を再生成し、再度 `validate-output.sh` を実行する
- **「いいえ、このままでOK」** → 「了解しました。」と回答する。ファイルが未提示なら提示し、提示済みなら回答のみで終了

## クオリティチェックリスト（B. コンテンツ品質）

出力前に確認する。A（フロー遵守）は `workflows/create.md`、C〜J（レガシートラックの実装）は
`workflows/legacy-build.md`。

- [ ] Web検索から得た実際の情報が含まれているか（架空データ NG）
- [ ] 出典でもユーザー提供でも確認できない数値・固有名詞・実績を、推測で書いていないか（`（要確認: …）` にしたか）
- [ ] 完了報告に 7 項目がそろい、要確認の一覧と未実施の検証が書かれているか
- [ ] 提示の前に自己検証（Step 5-B）を行ったか。撮影できたときは全スライドの画像を見たか。撮影していないのに「見た目を確認した」と書いていないか
- [ ] 出典 URL が参考リンクスライドに含まれているか
- [ ] スライド枚数が選択モードに合致しているか（CLIトラック: 実効仕様の目安 / レガシー: 6〜10 枚 / ミニ: 3 枚固定）
- [ ] CLIトラックで、出典なし・未知の type・形式不正・切り捨ての warn が 0 件になっているか（`--strict` の exit 0 だけで合格にしていないか）
- [ ] `tone: dark` は 1〜2 枚までに収まり、`contrast` や `steps` を多用していないか

# Audience & Purpose — 目的別トーン定義

スライド資料は「誰を、どこへ動かしたいか」で構成・トーンが決まる。
このファイルは、Step 0 で確認した**作成目的**ごとに、Step 3（構成設計）と
Step 4（生成）で適用する「強調する階層・説得のレバー・引き算方針」を定義する。

**大原則（全目的共通）**:
- **中身が9割・見た目が1割**。デザインより先にメッセージとストーリーラインを確定する
- **ワンスライド・ワンメッセージ**
- 事実に基づく（数値・引用は出典必須。AIが「型」として置いた例は必ず実データに差し替えるよう促す）

---

## 目的の3分類

| 目的 | 向かうベクトル | 本質 | 技術アナロジー |
|---|---|---|---|
| **A. 自己学習・振り返り** | 自分（内省） | 自身の「OSアップデート」 | デバッグログ / ローカルブランチ |
| **B. 社内共有・勉強会** | 内側（チーム） | 知識の「共有資産」化 | README.md / APIリファレンス |
| **C. SNS発信・顧客プレゼン** | 外側（市場・顧客） | 感情を動かし行動を促す | 本番UI/UX / マーケLP |

---

## A. 自己学習・振り返り用

**評価関数**: 内省の深さと論理の堅牢性

| 観点 | 適用方針 |
|---|---|
| 強調する階層 | **Why So（なぜそう言えるか）** を縦に深掘り。結論だけでなく論理構造を見せる |
| 構成 | 経験 → 教訓（抽象ルール）への変換を促す（コルブの経験学習モデル）。「この経験から得た再利用可能な教訓」を1枚入れる |
| 説得レバー | 自分への問い。「思考に偏り（バイアス）はないか」のチェックリストを添える |
| 引き算方針 | 装飾は最小。思考の垂直構造（論理のツリー）が見えることを優先 |
| 推奨 type | points（Why So の展開）、summary（教訓の言語化）、diagram（論理構造） |
| トーン | 率直・分析的。自分向けなので敬語や体裁は最小限 |

## B. 社内共有・勉強会用

**評価関数**: 既存業務との接続性と、明日からのアクションの具体性

| 観点 | 適用方針 |
|---|---|
| 強調する階層 | **What（共通言語化）＋ How（再現可能なアクション）**。「自社の既存事業・課題とどう繋がるか」を明示 |
| 構成 | 情報の羅列ではなく「論点（問い）」を提示し、聞き手が当事者意識を持てるようにする |
| 説得レバー | 腹落ちの設計。指示・演説ではなく、相手が判断できる材料を出す |
| 引き算方針 | 共有資産として後から参照されるため、要点の構造化を優先（見出し・箇条書き） |
| 推奨 type | points（論点提示）、table（比較・整理）、summary（アクションプラン）、feature-showcase（機能・手順紹介） |
| トーン | 平易・実務的。専門用語には補足。「明日から何をするか」で締める |

## C. SNS発信・顧客プレゼン用

**評価関数**: ベネフィット（利得）の明快さと、行動の緊急性

| 観点 | 適用方針 |
|---|---|
| 強調する階層 | **感情 → 規範 → 利得** の順（説得の3層構造）。いきなりロジック（利得）から入らない |
| 構成 | AIDMA導線：注目（Attention）→ 想像（Desire）→ 行動（Action）。最後に情熱と自信で締める |
| 説得レバー | 相手の感情を動かし、具体的な次の行動を促す。緊急性（今動かないリスク）を提示 |
| 引き算方針 | **徹底的な引き算**。色・線・文字を極限まで減らし「瞬間的に伝わる」構成 |
| 推奨 type | title（強い一言）、chart（一目でわかる数値）、comparison-chart（before/after）、summary（行動喚起） |
| トーン | 明快・情緒的。専門用語は避け、ベネフィットを主語にする |

---

## ネクストアクションの定義（C で特に重要・A/B でも推奨）

資料のゴールは「完成」ではなく「相手を動かすこと」。
**受け取った相手が30秒後に最初にとるべき具体的な行動**を、最終スライド付近に含める。

- A（自己学習）: 「次に試す・検証する1つ」
- B（社内）: 「明日からの具体的アクション1つ」
- C（顧客）: 「今すぐとってほしい行動1つ（＋今動く理由）」

---

## Verifier（生成時の注意・全目的）

- **手段の目的化を戒める**: ユーザーが「スライド10枚」と枚数を先に指定した場合、
  「1枚の図の方が伝わりませんか？」等、より効果的な代替（資料を減らす選択肢）を提案してよい
- **社会的証明の扱い（C で特に）**: AIが置いた「成功事例・実績」はあくまで構成の型。
  必ず実在の事実に差し替えるようユーザーに明示する
- **完璧主義の回避**: ユーザーが悩み始めたら「まず6割の完成度で叩き台を出す」を優先

## 目的が未選択・未確定のときのフォールバック

Step 0 で目的が選ばれなかった場合（スキップ・後方互換ルート）は、
**B（社内共有）相当の中庸なトーン**を既定とする（平易・実務的・要点構造化）。
これは従来（v0.7.1 以前）の生成トーンにもっとも近い。

# help — このスキルの使い方を答える

> 先に読むもの: `references/usage-guide.md`。他の `workflows/*.md` は読まない。
> **このモードではスライドを作らない**。検索・MD の作成・変換も行わない。

## 起動する依頼

「このスキルの使い方を教えて」「websearch-slide-ja のヘルプ」「どう頼めばいい？」
「何ができるの？」「既定値を設定したい」など、使い方そのものを尋ねる依頼。

スライドの依頼と使い方の質問が一緒に来たとき（例: 「使い方を教えて。あと ○○ のスライドを作って」）は、
先に使い方を短く答え、続けてスライドの依頼のモードに進む。

## 返す内容

質問に応じて、該当する部分だけを短く返す。漠然と使い方を聞かれたときは 1 → 2 → 3 の順に返す。

1. **できること 4 つと頼み方の例**（`references/usage-guide.md`「できることと頼み方」）
2. **今の環境の状態**（下の「環境の確かめ方」。確かめた結果だけを書く）
3. **プロジェクトに書いておくと便利な既定値**（`references/usage-guide.md`「既定値の雛形」を
   コードブロックのまま示す）

質問が 1 つに絞られているとき（例: 「MD から変換するにはどう頼む？」「既定値は何を書ける？」）は、
その部分だけを答える。全部を並べない。

## 環境の確かめ方

シェルを実行できる環境でだけ行う（手段は `references/environment.md`）。**何もインストールしない**。

| 確かめること | 方法 | 伝える内容 |
|---|---|---|
| `mdss-convert` の有無と版 | `mdss-convert --version`（無ければ `npx -y mdss-convert@latest --version`） | 使える → CLIトラック（版つき）。使えない → レガシートラック（従来方式）で作成 |
| Playwright の有無 | `node assets/scripts/capture.mjs --check`（終了コード 0＝使える／3＝使えない） | 使える → 生成後に全スライドを撮影して見た目を確認。使えない → lint（または機械的な検証）まで |

- この会話で診断済み（`workflows/build.md`「Step 2.5」）なら、その結果を使い回す
- シェルを実行できない環境では確かめず、「この環境では確かめられません」と書く。
  推測で「使えます」と書かない

## 既定値の雛形を示すときの約束

- 雛形は**見せるだけ**にする。`CLAUDE.md` やプロジェクト指示を、スキルが勝手に編集しない
- ユーザーが「書き込んで」と頼んだときだけ、書き込み先のファイルと追記する内容を示して確認し、
  追記する（既存の内容は書き換えない）。Claude.ai では、プロジェクト指示への貼り付けは
  ユーザーが行う
- 雛形の値はユーザーの例であり、推奨値ではないことを添える。書かない項目は従来どおり質問する

# CLI連携（mdss-convert）— 診断・変換・逆抽出（v0.8.2）

Step 2.5（診断・実効仕様の取得）・Step 4-A（MD生成）・Step 4-B（変換）・エントリポイントC（逆抽出）で参照する。
**このスキルはmdss-convertの特定バージョンに依存しない。** 実行前に毎回「今何が使えるか」を
`--help`の出力から確認し、その結果に応じてコマンドを組み立てる（プリフライト方式）。

`mdss-convert`が使えない場合は本ファイルを一切使わず、従来どおり
`markdown-format.md` / `slide-layouts.md` / `assets/` によるLLM直接生成（レガシートラック）を行う。

---

## 1. 全体像：CLIトラックとレガシートラック

```
Step 2.5（診断） ─┬─ CLIが使える  → CLIトラック（本ファイルに従う）
                  └─ CLIが使えない → レガシートラック（本ファイルは使わない。従来どおり）
```

両トラックとも正式にサポートする経路であり、優劣ではなく「使えるものを使う」という関係。
CLIトラックとレガシートラックで生成されるスライドの仕様（対応type・見た目）は**一致しない**
ことがある。これは仕様であり、不具合ではない。

---

## 2. Step 2.5: CLI環境診断（プリフライト）

**このステップは会話内で一度だけ実行し、結果を以降のStep 3-0/3/4-A/4-B・エントリポイントCで使い回す。**
新しい会話（このスキルを再度呼び出したとき）では、毎回この診断からやり直す。

### 2-0. 実行タイミング

| エントリポイント | 実行する位置 |
|---|---|
| A) テーマの依頼 | Step 2（情報収集）の後、**Step 3-0（ビジュアル化判定）の前** |
| B) スライドMDの変換 | 変換（Step 4-B）の直前 |
| C) HTML→MD逆抽出 | 逆抽出の直前 |
| D) 未準拠MD・CSV・会話履歴 | 入力タイプ判定の後、**スライドMDへ変換する前** |

A と D で構成より前に実行するのは、使える type・枚数の目安・パレットがCLIの版で変わるため。
構成を決めた後に診断すると、取得した仕様が構成に反映されない。

### 2-1. 可用性判定

```bash
command -v mdss-convert                    # グローバルインストール済みか
# 無ければ:
npx -y mdss-convert@latest --version       # レジストリから解決できるか（バージョンは固定しない）
```

- タイムアウト／ネットワーク不通／0以外の終了コード → **CLI利用不可** と判定し、レガシートラックへ進む。
  この場合、以降の指示（本ファイルの§3〜）はすべて無視してよい
- 成功（バージョン文字列が出力される） → 2-2 へ

### 2-2. 機能検出（`--help` の出力をテキスト照合するだけ。実行して試さない）

```bash
mdss-convert --help    # またはグローバル未導入なら npx -y mdss-convert@latest --help
```

出力に以下の文字列がそのまま含まれているかどうかで、対応可否を判定する（完全一致でgrep）。
**未対応と思われる場合は安全側（非対応扱い）に倒す**こと。

| 判定する文字列 | 対応時に使えること |
|---|---|
| `--print-spec` | スライドMD記法の最新仕様書を都度取得できる（§3） |
| `--strict` | lintにerrorがあればHTML未生成でexit 3にできる（§4） |
| `--json-only` | 変換せずメタ情報のみ取得できる（`--strict`非対応時の代替判定に使う） |
| `--extract-md` | HTML→MD逆抽出をCLIに任せられる（§5） |
| `--guide-prompt` | type の選び分け指針と構成フレームを取得できる（§3-2） |
| `--sample-md` | 全 type の実例を取得できる（§3-3。迷ったときだけ使う） |
| `--quiet` | 警告・書き出しメッセージを stderr に出さない（§4） |

あわせて、`--palette` の行に並ぶID（例: `ocean|ruby|forest|sunset|plum|gold|graphite`）を
**使えるパレットの一覧**として控える。`--print-spec` の frontmatter 表と食い違うときは
`--help` を正とする（v0.6.1 では `--print-spec` が5色、`--help` と実際の動作が7色）。

「対応可否」とパレットIDは会話内メモとして保持し、以降のStep 4-B・エントリポイントCで使い回す。

### 2-3. レガシートラックへの切替を伝える

Step 2.5でCLI利用不可と判定した場合、Step 3-0に進む前にユーザーへ一言添える。

> 「今回はCLI（mdss-convert）が利用できないため、従来方式でスライドを作成します。
>   対応するスライド種類や見た目がCLI版と一部異なる場合があります。」

## 3. 実効仕様の取得（Step 2.5 の続き）

診断でCLIトラックと決まったら、その場で実効仕様を取得する。**取得は会話内で各1回**
（Step 4-Bを複数回実行しても再取得しない）。

### 3-1. `--print-spec`（記法の正）

```
--print-spec 対応:
  mdss-convert --print-spec を実行し、その出力（スライドMD記法の最新仕様）を
  Step 3-0・3（構成）と Step 4-A（MD執筆）にそのまま使う。references/markdown-format.md は使わない

--print-spec 非対応（または未検出）:
  references/markdown-format.md をそのまま使う（レガシートラックと同じファイル）。
  検証済み: markdown-format.md（v0.7.0）のtitle／chart-donut／diagram-flow／`layout: two-col`／sources
  の記法は、mdss-convert v0.6.1 でそのまま変換できる。
  つまり「仕様書としては古くても、変換自体は問題なく通る」
```

`--print-spec`の出力はそのままコンテキストに読み込んでよい（v0.6.1 で約150行・9KB）。
読み取るのは次の5点: **type 一覧／共通記法／`layout:` の値／type 別の制約（上限）／枚数の目安**。

### 3-2. `--guide-prompt`（選び分けの参考）

```
--guide-prompt 対応:
  mdss-convert --guide-prompt を実行して読む（v0.6.1 で約8KB）
```

使うのは次の2か所だけ。

- **type の選び分け指針**（太字の文。例: 手順は `steps` を優先、時系列は timeline、`contrast` は頻用しない）
- **「構成フレーム」**（title → 概要 → メイン → summary → sources）

使わないもの・注意点:

- このプロンプトに原稿作成を丸ごと任せない。目的確認・ロール推定・検索・出典管理は本スキルの
  Step 0〜3 で行う。末尾の「テーマ」欄は使わない
- **記法の説明が `--print-spec` と食い違う箇所は `--print-spec` を正とする**
  （v0.6.1 では `comparison-chart` の記法説明が食い違う。`tone: dark` の枚数目安も異なるため、
  少ない側の「1〜2枚」に合わせる）
- 非対応の版では読まずに進める（`--print-spec` と SKILL.md Step 3 の表で足りる）

### 3-3. `--sample-md`（迷ったときだけ）

全 type の実例（v0.6.1 で約15KB・25枚）。**全文は読まない。**
初めて使う type の書き方が `--print-spec` だけでは決めきれないときに限り、ファイルに出力して
該当 type のスライドだけを読む。

```bash
mdss-convert --sample-md -o <作業用の場所>/sample.md
grep -n '<!-- slide: steps' <作業用の場所>/sample.md     # 行番号を調べ、そのスライド（次の --- まで）だけ読む
```

出力先は成果物のフォルダではなく一時的な場所にし、ユーザーには提示しない。

## 4. Step 4-B: 変換コマンドの組み立て

```
base = "mdss-convert"（グローバル導入時） または "npx -y mdss-convert@latest"

--strict 対応:
  ${base} <deck.md> -o <deck.html> --strict --json
  → exit 3: lintにerrorがある。MDを修正して再実行する（HTMLは生成されていない）
  → exit 0: HTMLは生成されたが、**合格とは限らない**。JSON中のwarnings/lintを読み、
    §4-1 の表で判定する

--strict 非対応（または未検出）:
  ${base} <deck.md> -o <deck.html> --json
  → 出力JSONのlint配列を自分で確認し、level: "error" が1件でもあれば
    「HTMLは生成されているが、MDを修正して再変換することを推奨する」旨をユーザーに伝える
    （--strictと同等の安全性を、スキル側の判定で代替する）

パレット／テーマの上書き要求（「ダークで」「別の色で」等）:
  --palette <id> / --theme <id> を付与する。frontmatterは書き換えない
  （恒久化したい場合のみ、frontmatterの`palette:`を編集して再変換）
```

`--quiet` 対応時は付けてよい（stderr の警告・書き出しメッセージを止める。判定は stdout の JSON で行う）。
標準入力から読む場合は入力パスを `-` にする（`cat deck.md | ${base} - -o deck.html --strict --json`）。
ファイルに保存したMDを渡すのが基本で、stdin は保存前の事前確認に使う程度でよい。

### 4-1. lint の扱い（`--strict` 任せにしない）

`--strict` が止めるのは `level: "error"` だけで、error になるのは frontmatter の欠落や
`contrast` の `example` 欠落など一部に限られる。**出典なしのグラフ・未知の type・ブロックの
形式不正は `warn` のまま exit 0 になり、HTMLも出力される**（v0.6.1 で確認）。
本スキルが必須とするルール（出典の明記など）はスキル側で判定する。

| lint / warnings の内容 | 扱い | v0.6.1 のメッセージ例 |
|---|---|---|
| `level: "error"` | HTMLを提示しない。MDを直して再変換 | `frontmatter（--- title: ... ---）が見つかりません` |
| 出典が無い（chart / figure の `source`） | **error と同じ扱い** | `chart の source（出典）がありません（出典明記は必須ルール）` |
| 未知の type | **error と同じ扱い**（別の type で描画されてしまう） | `未知の type "foo" は points として描画します` |
| 最終スライドが `sources` でない | **error と同じ扱い**（3枚ミニモードを除く） | `最終スライドが sources（出典）ではありません` |
| ブロックの形式不正（描画されない） | MDを直して再変換（内容が欠ける） | `steps ブロックの形式が不正です` |
| 切り捨て・不正値のフォールバック | MDを直して再変換（内容が欠ける） | `chart の系列が 6 件あります（最大5件・6件目以降は切り捨て）` |
| 上記以外の warn / info | 再変換しない。完了時に要約して伝える | `外部画像を含むため、PNG/ZIP出力が失敗する可能性があります（CORS制約）` |

- **メッセージ例は判定の手がかりであり、文言の完全一致で判定しない**（ツール側で変わりうる）。
  warn / error が1件でもあれば内容を読み、上の表のどれに当たるかを判断する
- lint の `slide` は **0始まり**（`slide: 1` は2枚目）。ユーザーに伝えるときは1始まりに直す
- 直して再変換するのは、対象の warn / error が0件になるまで
- ユーザーが用意した MD・データ（エントリポイント B / D）で出典が無いときは、勝手に削らず、
  まず出典をユーザーに確認する（ユーザー自身のデータなら `source` に「ユーザー提供データ」と書く）。
  確認できないグラフは数値を作らず、テキストのスライドに置き換えて、その旨を完了時に伝える
- 会話のみモード（通常の枚数）では出典URLが無い。最終スライドは `sources` のまま、
  「会話で提供された内容に基づく」と1行書く（リンクでなくても lint は通る）
- **例外（3枚ミニモード）**: 構成が「サマリ／本文／まとめ」の3枚固定で、最終スライドが `sources` に
  ならない。この場合の「最終スライドが sources でない」は再変換の対象にせず、完了時に伝える側に回す
  （参考リンクがあれば「まとめ」に書く）。それ以外のモードでは最終スライドを必ず `sources` にする
- HTMLを出さずに確認だけしたいときは `--json-only` を使う（`${base} <deck.md> --json-only`）

### 4-2. 終了コード

| コード | 意味 | スキルの対応 |
|---|---|---|
| 0 | 正常（warn があっても 0） | §4-1 で lint を判定する |
| 1 | 入出力エラー（入力ファイルが無い等） | パスを確認して再実行。CLIの不具合ではない |
| 2 | 引数エラー（未対応のオプション等） | 診断結果と付けたオプションを見直す（§7） |
| 3 | `--strict` 違反（lint に error。HTML未出力） | MDを直して再変換 |
| 4 | 原稿MDを抽出できない（`--extract-md`） | LLM逆抽出にフォールバック（§5） |

### スタイル変更の対話（CLIトラック）

「3枚目を2カラムにして」等の指示があった場合:

1. 対象スライドのディレクティブに `layout:` を追記する（例: `<!-- slide: points, layout: two-col -->`）
2. 上記コマンドで再変換する（Step 2.5の診断結果は使い回す。再診断しない）
3. 指示が曖昧なとき（「もっと見やすく」等）は `ask_user_input_v0` で選択式提示する

利用可能な `layout:` / `tone:` の値は、Step 2.5で取得した実効仕様（`--print-spec`の出力、
または非対応時は`markdown-format.md`の記載範囲）に従う。

## 5. エントリポイントC: HTML→MD逆抽出

```
extract-md 対応 かつ 対象HTMLに "const DECK_MD =" を含む:
  mdss-convert --extract-md <deck.html> -o <deck.md>
  → 推論不要・完全可逆でMDを復元する

それ以外（CLI利用不可／extract-md非対応／旧スキル生成HTML等でDECK_MDを含まない）:
  従来のLLM逆抽出（markdown-format.md §7）にフォールバックする
  → この場合「デッキ固有のカスタムCSS・微調整はMDに持ち越せない」旨をユーザーに明示する
    （markdown-format.md §7の限界事項どおり）
```

`mdss-convert --extract-md <file>` は非対応時（対象HTMLがmdss-convert生成物ではない等）、
`exit 4` かつ「原稿MD（DECK_MD）が見つかりません」とstderrに出力する。これを検出したら、
即座に従来のLLM逆抽出へフォールバックしてよい（CLIが壊れているわけではない）。

## 6. オプションの使い方（まとめ）

| オプション | 本スキルでの使い方 |
|---|---|
| `--print-spec` | Step 2.5 で1回取得。**記法の正**（§3-1） |
| `--guide-prompt` | Step 2.5 で1回取得。選び分け指針と構成フレームだけ参考にする（§3-2） |
| `--sample-md` | 迷ったときだけ、該当 type の部分だけ読む（§3-3） |
| `--strict` / `--json` | 変換時に常に付ける（対応時）。結果は §4-1 で判定 |
| `--json-only` | HTMLを出さない事前確認、または `--strict` 非対応時の代替判定 |
| `--quiet` | 任意。stderr を静かにする |
| `--palette` / `--theme` | ユーザーが一時的な上書きを求めたときだけ |
| `--extract-md` | エントリポイントC（§5） |

**動作確認済みの版: mdss-convert v0.6.1**（2026-11 時点。`--help` の文字列照合・`--print-spec`・
`--guide-prompt`・`--sample-md`・`--strict --json`・`--json-only`・stdin・`--extract-md`・
終了コード 0〜4・`palette: gold` を確認）。これは確認した版の記録であり、版の固定ではない（§8）。

## 7. なぜ「実行して試す」のではなく「`--help`を見る」のか

未対応のオプション（例: 古いCLIに`--strict`）をそのまま変換コマンドに付けて実行すると、
`不明なオプション: --strict` として`exit 2`になり、**変換そのものが失敗する**（確認済み）。
本番の変換コマンドで試行錯誤するのは事故のもとなので、`--help`の出力をテキスト照合するだけの
安全な方法で先に判定する。

---

## 8. バージョン指定について

`npx -y mdss-convert@latest` を既定とし、特定バージョンに固定しない。
mdss-convert側の機能追加・改善をスキルの改修なしに享受するための意図的な選択であり、
将来オプションの対応状況が変わっても本ファイルの§2-2（機能検出）がそのつど吸収する。
万一mdss-convert自体が利用不能になっても、レガシートラックが常に生きているため
スキル全体が機能不全になることはない。
